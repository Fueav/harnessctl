# harnessctl v0.3.0 Optional Built-ins Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Implement `docs/spec-v0.3.0-optional-builtins.md` exactly: gate-set-driven built-ins, mandatory safety gates, basename-only boundary globs, and v0.3.0 release surfaces.

**Architecture:** Keep configuration authority in `scripts/lib/harness_config.py`, expose one line protocol for resolved profile gates, and let both shell runners guard their existing gate invocations through a preloaded enabled set. Extend the shared boundary parser with basename-only `fnmatchcase` semantics so verify and finalize use identical trusted behavior.

**Tech Stack:** Go CLI wrapper, Python 3 standard library, Bash runners/tests, JSON configuration.

## Global Constraints

- Schema remains version 2 and v1 normalization behavior remains unchanged.
- `change_scope` and `ai_boundaries` are mandatory in every gate set.
- Candidate/release profiles additionally require `release_context_before` and `release_context_after`.
- Built-ins must be a subsequence of the exact 20-member `BUILTIN_GATE_ORDER`.
- Only basename globs containing `*` are added; `?`, bracket syntax, path globs, `*`, and `**` remain invalid.
- Custom gate semantics and approval-variable semantics remain unchanged.
- Engine version becomes `v0.3.0`.
