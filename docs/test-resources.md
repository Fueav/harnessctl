# Resource lifecycle contract (v0.8.1)

This additive CLI implements the approved disposable dependency lifecycle. `resources run --repo ROOT [--mode shared|fresh] -- COMMAND...` requires the consumer's exact version lock and schema-1 `harness/dependencies.json`. `resources status` is observational; `resources gc [--all-idle]` only reconciles recorded, labeled test resources. No daemon, global Docker prune or service installation is performed.

Consumer configuration declares `enabled`, `isolation: database-per-run-v1`, PostgreSQL/Redis images and resource settings, and `limits`. Unknown fields fail closed. Absence of configuration leaves existing native test gates unchanged; `enabled: false` explicitly runs a service-free command. Consumers must adapt every test client to injected database, Redis DB and authentication settings before opting in. Native change/coverage/race gates use shared dependencies in development and fresh dependencies in the release profile.

State is private and stored under `$XDG_STATE_HOME/harnessctl/resources` (default `~/.local/state/harnessctl/resources`), keyed by common Git directory and Docker daemon identity. A lock serializes allocation, release and GC. Durable intent precedes creating each environment or run. Resource IDs are random and ownership labels must match state before mutation. Docker errors, corrupt records and ownership conflicts preserve resources and report failure.

Each compatible shared environment contains one PostgreSQL and one standalone Redis service, bounded logs, named test volumes and a network. Each run gets a new PostgreSQL database/role, two distinct Redis logical DBs and a Redis user denied dangerous/server-admin commands. Existing business databases are never adopted. Images are resolved to actual IDs; application commits and worktrees do not split compatible service pools. Unavailable images are pulled as declared, never substituted.

The supervisor registers a child process before allowing it to execute. Exit, failure and signals stop writers, remove task data, verify deletion and release ownership. With default `max_idle_environments: 0`, the last task removes owned containers, network and volumes before returning; overlapping tasks still share services. Killing only the invoking CLI is handled by its surviving supervisor. Killing that supervisor (including during allocation/deletion), rebooting, Docker unavailability or failed cleanup requires a later `run/gc`, using process start/boot identity, not TTL alone. Stopped dependencies can be discarded without SQL only after every lease is recoverable and all owned writers stop. Failed cleanup remains pending, blocks more allocations and is retried. Unprovable orphan ownership is preserved. `--retain-on-failure` explicitly keeps bounded debug data after stopping writers; ordinary failed tests retain no database.

Owned application containers use `--label-file "$HARNESS_RESOURCE_LABEL_FILE"`, `--env-file "$HARNESS_RESOURCE_ENV_FILE"` and `--network "$HARNESS_RESOURCE_NETWORK"`. Build images with the same labels so recovery can find them. Container cleanup always removes associated anonymous volumes; named service volumes are removed only with an idle owned environment. No caller may share these labels with business resources.

Budgets cover run/environment counts, owned data plus bounded service logs, and host/VM free space. Capacity waits are bounded; storage pressure does not repeatedly create replacement services. Initial service cost is checked before data allocation. Idle environments may be reclaimed under pressure, but active environments are never evicted to admit another run. Read-only disk sampling retries at most three times, each within ten seconds; partial, invalid or persistently unavailable measurements cannot admit work. Runtime sampling reports project pressure and blocks admission; aggregate usage cannot identify a culprit, so active commands keep their data and remain subject to their own timeout. The bounded result separates command exit, cleanup, final exit and pressure. Explicit `max_idle_environments > 0` opts into idle reuse; `idle_seconds` is checked only at a later `run/gc`, with no timed reclamation guarantee. `status` is read-only. Debug retention expiry likewise requires `run/gc`. Configuration thresholds are initial safety settings, not a benchmark or hard filesystem quota. Docker.raw actual allocated bytes, when locally available, are reported separately; the engine never shrinks or deletes the Docker virtual disk.

Validation includes unit/fault tests, configuration-only consumer fixtures, cross-worktree identity, different migration versions, concurrent same-key isolation, process/signal failure, retry after cleanup failure, foreign-resource preservation and repeated real Docker runs. Release v0.8.1 before updating consumer locks/installations; an explicit existing `max_idle_environments: 1` must also change to `0` to enable immediate reclamation. Schema 1 and opt-in reuse remain compatible. Until release, use a matching candidate binary. Tests distinguish real Docker execution from reboot/fault simulation; no test reboots the host.
